01

Set up your check

Start with a fictional example, then edit it to explore the result.

One KEY=VALUE per line. Quotes and comments supported; no expansion or multiline values. Duplicate keys and malformed quotes are errors.

Root: keys + optional allowUnknown. Each key: required, type, regex, enum, secret. Types: string, number, integer, boolean, url, enum.

How this check works
Bounded regex language: patterns must be anchored ^...$. Use literals, character classes, ., escapes \d \w \s (and uppercase inverses), or single-atom repetitions ? * + {n} {n,m}. No groups, alternation, backreferences, flags or lookarounds. Matching uses bounded dynamic programming.
Required means present; an empty string is allowed unless type, enum or regex rejects it. Booleans are exactly true/false; URLs must use http or https. Masking uses schema secret flags plus key-name heuristics and cannot identify every sensitive value. Templates stay visible in the input fields. Use fictional data only.
Limits and grammar are documented in the local README. No installation, account, tracking, browser storage or network connection is required.
